# testability-heuristics Skill — Plan

## Top-Level Overview

`testability-prep` currently uses `seams-reference.md` as its sole barrier checklist — five
generic barrier types with minimal sub-categorization. The goal of this work is to:

1. Create a new `SKILLS/testability-heuristics/` skill directory with:
   - `SKILL.md` — installable skill definition that Bob can invoke independently.
   - `heuristics-reference.md` — a **purely universal** barrier reference, free of any
     framework or language specifics. It expands the original five barriers with nuanced
     sub-categories and adds new universal barriers (async coupling, global state, env vars,
     import-time side effects). It is the stable, framework-agnostic foundation from which
     project-specific heuristics are derived.

2. The `testability-heuristics` skill, when invoked, reads the project context produced by
   `analyze-codebase` (`TESTING.md`, `CONVENTIONS.md`) and uses the universal reference as a
   base to **compose** a project-scoped `.bob/HEURISTICS.md` — translating abstract barrier
   patterns into concrete, language- and framework-aware signals specific to the repo at hand.

3. Update `testability-prep`'s `SKILL.md` so that Step 3 reads `.bob/HEURISTICS.md` when
   available (the project-scoped version), falls back to reading `heuristics-reference.md`
   directly when not, and only uses `seams-reference.md` as a last resort.

`seams-reference.md` is **not deleted** — it remains a last-resort fallback, but its role
shifts entirely to the new `heuristics-reference.md` + the skill-generated `.bob/HEURISTICS.md`.

## Sub-Task 1 — Author `heuristics-reference.md`

**Intent**
Create a **framework-agnostic**, universal barrier reference that is the stable foundation
the skill builds project-specific heuristics from. It must describe *what* each barrier is
in terms of fundamental testability concepts — observable output, controllable input, isolated
boundary — without referencing any specific language or framework. Stack-specific phrasing
belongs only in the project-scoped `.bob/HEURISTICS.md` generated in Sub-task 2.

**Expected Outcomes**
- `SKILLS/testability-heuristics/heuristics-reference.md` exists.
- Contains **only universal content**: no framework names, no language keywords, no
  framework-specific APIs. Examples use pseudocode or abstract descriptions only.
- All 5 original barriers from `seams-reference.md` are present, expanded with richer
  "signal" descriptions and more detailed minimum-fix guidance.
- Four new universal barriers added:
  - A6: Uncontrollable async boundary — a deferred or concurrent operation is initiated inside
    the unit with no way for a test to await, cancel, or substitute its trigger.
  - A7: Global or singleton state mutation — shared mutable state at module/process scope is
    written by the tested code, making test order matter and isolation impossible.
  - A8: Environment/configuration coupling — behavior branches on a value read directly from
    the process environment or a global config object, with no override path for tests.
  - A9: Opaque initialization side effect — the module or object performs observable side
    effects at load/construction time that cannot be suppressed or observed in isolation.
- Each barrier follows the same table format as `seams-reference.md` but with an added
  **"Adaptation hint"** row: a one-sentence instruction to the skill (Sub-task 2) explaining
  what project-specific information to inject when generating `.bob/HEURISTICS.md`
  (e.g., "Replace 'I/O call' with the specific client library name found in DEPENDENCIES.md").
- A "How to use this reference" section at the top that explicitly states: this file is
  framework-agnostic; do not apply it directly to diff scanning; use `.bob/HEURISTICS.md`
  (generated by the skill) for concrete barrier detection instead.
- Quick-reference decision table (same format as `seams-reference.md`).

**Todo List**
1. Create `SKILLS/testability-heuristics/` directory by writing the first file into it.
2. Write `heuristics-reference.md` with:
   - Preamble: "This is a universal reference. It is not read directly during diff analysis.
     The `testability-heuristics` skill uses it as a base to generate `.bob/HEURISTICS.md`,
     which is the file that `testability-prep` reads."
   - Barriers A1–A9, each as a two-column table with rows: Description, Signal (abstract),
     Minimum fix (abstract), Do NOT do, Adaptation hint.
   - Quick-reference decision table.
3. Verify no barrier entry contains a framework name, language keyword, or concrete API name
   — use only abstract terms ("the I/O client", "the time source", "the async trigger", etc.).

**Relevant Context**
- `SKILLS/testability-prep/seams-reference.md` — source content to expand from; note that
  its examples use concrete language syntax which must be abstracted away in the new file.
- Same two-column table format: `| Field | Value |` rows per barrier.

## Sub-Task 2 — Author `SKILLS/testability-heuristics/SKILL.md`

**Intent**
Define the `testability-heuristics` skill so it is independently installable and invocable.
When invoked, it reads project context produced by `analyze-codebase` and translates the
universal `heuristics-reference.md` into a concrete, project-adapted `.bob/HEURISTICS.md`
— replacing abstract descriptions with real library names, real file paths, and real
framework idioms discovered in the repo. The generated file is what `testability-prep` reads
during barrier scanning; it must never need further interpretation.

**Expected Outcomes**
- `SKILLS/testability-heuristics/SKILL.md` exists with valid YAML frontmatter.
- The skill, when triggered, produces `.bob/HEURISTICS.md` where every barrier entry
  references concrete project details (e.g., "axios" instead of "the HTTP client",
  "jest.useFakeTimers()" instead of "freeze the time source").
- Each barrier in the generated file retains the same table structure as
  `heuristics-reference.md` but with the "Adaptation hint" row removed and replaced by
  concrete, project-specific language in the Description, Signal, and Minimum fix rows.
- Only barriers relevant to the detected stack and patterns are included; irrelevant
  barriers (e.g., UI selector barriers in a pure API service) are omitted with a brief note.
- The generated file opens with a header block: detected stack, `analyze-codebase` files
  consulted, date generated.
- The skill is independently useful outside of `testability-prep`.

**Todo List**
1. Write `SKILLS/testability-heuristics/SKILL.md` with:
   - YAML frontmatter: `name: testability-heuristics`, description explaining standalone use.
   - Step 1 — Gather project context: read `.bob/TESTING.md` (or `TESTING.md`),
     `.bob/CONVENTIONS.md` (or `CONVENTIONS.md`), `.bob/DEPENDENCIES.md` (or `DEPENDENCIES.md`),
     `.bob/ARCHITECTURE.md` (or `ARCHITECTURE.md`) if they exist. If none exist, `glob` for
     representative source files to infer language, framework, and I/O libraries.
   - Step 2 — Load the universal reference: call `read_file` on
     `SKILLS/testability-heuristics/heuristics-reference.md`.
   - Step 3 — Adapt each barrier: for each of A1–A9, apply the barrier's "Adaptation hint"
     together with the gathered project context to rewrite the Description, Signal, and Minimum
     fix rows with project-specific concrete terms. Omit barriers with no relevant signal in
     the project (state the reason in a "Skipped barriers" section at the end of the output).
   - Step 4 — Write `.bob/HEURISTICS.md`: write the adapted barriers as a new file (same
     table format, no Adaptation hint rows), preceded by the header block.

**Relevant Context**
- `SKILLS/analyze-codebase/SKILL.md` — pattern for reading and generating context files.
- `SKILLS/testability-heuristics/heuristics-reference.md` — the universal source to adapt from.
- The "Adaptation hint" row in each barrier entry is the instruction to Sub-task 2's skill
  for what to concretize; it should not appear in the generated `.bob/HEURISTICS.md`.

**Status** — `[x] done`

project-adapted `.bob/HEURISTICS.md` when available — the file that already contains

`seams-reference.md` becomes a last-resort fallback only.

  barriers (e.g., skip A1 UI-selector barrier if the diff contains no UI files).
- `seams-reference.md` is mentioned as a final fallback only if `heuristics-reference.md` is
  not found.
- No other steps in `testability-prep` change.
