# context-window

Capture the current Bob conversation context and export it as a portable handoff bundle. Follow
every step in order. Name the exact tool used at each action.

---

## Step 1 — Argument validation

1. Check whether an `[output-file]` argument was supplied with the `/context-window` command.
2. If an argument **was** provided, use it as `OUTPUT_FILE`.
3. If **no** argument was provided, set `OUTPUT_FILE` to `context-handoff.md`.
   Do **not** prompt the user — `context-handoff.md` is the default.

---

## Step 2 — Workspace snapshot

Gather the static facts about the workspace that any incoming developer will need.

1. Call `execute_command` with `git log --oneline -10` to collect the 10 most recent commits.
   If the command fails (not a git repo), note "not a git repository" and continue.
2. Call `execute_command` with `git status --short` to identify any uncommitted changes.
3. Call `list_files` on the workspace root (non-recursive) to enumerate the top-level structure.
4. Attempt to `read_file` each of the following files if they exist (skip silently if absent):
   - `README.md` (or `README`)
   - `AGENTS.md`
   - `.context/PROJECT.md`
   - `.context/ARCHITECTURE.md`
   - `.context/CONVENTIONS.md`
   - `package.json` / `pyproject.toml` / `Cargo.toml` / `pom.xml` (whichever is present)
5. Store all gathered content in memory — do **not** write anything yet.

---

## Step 3 — Conversation distillation

Synthesise the live conversation into four structured sections. Work entirely from the messages
already present in this context window.

### 3.1 — Objective

Write one or two sentences describing what the user was trying to accomplish in this session.
Be concrete. If the goal shifted during the conversation, note both the original and current goal.

### 3.2 — Decisions & conclusions

List every explicit decision, choice, or conclusion reached during the conversation as a bullet
list. Each bullet must answer: *what was decided, and why?* If a decision was reversed or
superseded, include both the original and the replacement with a short note.

Examples of what belongs here:
- Technology or library choices
- Architectural patterns adopted or rejected
- Config values that were settled on
- Workflow steps that were agreed
- Edge cases explicitly ruled in or out

### 3.3 — Referenced files and repositories

For every file path or repository URL that was mentioned or read during the conversation:
- List the path / URL
- Write one sentence on *why* it was relevant
- Note its current state: `read`, `created`, `modified`, `deleted`, or `mentioned only`

### 3.4 — Open questions and next steps

List anything that was left unresolved, explicitly deferred, or flagged as a next action.
Each item should be a brief actionable bullet so the incoming developer knows exactly what to do.

---

## Step 4 — Assemble the handoff bundle

Build the complete Markdown document in memory using the template below. Substitute every
`<placeholder>` with real content from Steps 2 and 3.

```
# Bob Context Handoff

> Generated by the `context-window` skill.
> Load this file into a new Bob session to continue where the previous developer left off.

---

## How to use this file

1. Start a new Bob session in the same workspace (or clone the repo if needed).
2. Paste the contents of this file into the chat as your first message, or use
   `/context-window load` if that command is available.
3. Bob will ingest the context and you can continue the work immediately.

---

## Session metadata

| Field | Value |
|---|---|
| Exported at | <UTC timestamp ISO 8601> |
| Workspace | <workspace root directory name> |
| Git branch | <current branch or "N/A"> |
| Last commit | <hash and message of HEAD or "N/A"> |

---

## Workspace state

### Recent commits
<git log --oneline -10 output, or "N/A">

### Uncommitted changes
<git status --short output, or "none">

### Top-level structure
<list_files output formatted as a bullet list>

---

## Project summary

<Content from README.md — first 60 lines only. If no README, write "No README found.">

---

## Objective

<Content from Step 3.1>

---

## Decisions & conclusions

<Bullet list from Step 3.2. If none were reached, write "No explicit decisions recorded.">

---

## Referenced files and repositories

<Table or bullet list from Step 3.3. If none, write "No files explicitly referenced.">

---

## Open questions and next steps

<Bullet list from Step 3.4. If none, write "No open items recorded.">

---

## Agent context (AGENTS.md)

<Full content of AGENTS.md if found in Step 2, otherwise "No AGENTS.md found in this workspace.">
```

---

## Step 5 — Write the output file

1. Resolve the final UTC timestamp now (use `execute_command` with
   `powershell -Command "Get-Date -Format 'yyyy-MM-ddTHH:mm:ssZ' -AsUTC"` on Windows or
   `date -u +"%Y-%m-%dT%H:%M:%SZ"` on Unix/macOS). If both fail, use your internal estimate.
2. Substitute the timestamp and all remaining placeholders in the assembled document.
3. Call `write_file` to write the complete document to `OUTPUT_FILE`.
   Do **not** truncate any section — write the full content even if it is long.

---

## Step 6 — Summary report

Print the following to the chat:

```
## context-window — export complete

Output file : <OUTPUT_FILE>
Exported at : <UTC timestamp>

### Sections written
  ✓ Session metadata
  ✓ Workspace state      (<N> recent commits, <M> uncommitted changes)
  ✓ Project summary      (<source: README.md | no README>)
  ✓ Objective
  ✓ Decisions            (<count> items)
  ✓ Referenced files     (<count> items)
  ✓ Next steps           (<count> items)
  ✓ Agent context        (<source: AGENTS.md | not found>)

To continue this session in a new Bob chat, share <OUTPUT_FILE> and ask Bob to read it.
```

Mark any section that could not be populated with `✗` and append a short reason.
